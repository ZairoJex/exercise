## 5. 控制流：程序不再只能从上到下一路执行

“控制流”是代码语句实际执行的顺序。

普通代码从上到下执行：

```python
print("第一步")
print("第二步")
print("第三步")
```

输出一定是：

```text
第一步
第二步
第三步
```

加入分支后，某些语句可能执行，也可能不执行：

```python
score = 95

if score >= 60:
    print("及格")

print("统计结束")
```

加入循环后，同一段语句可以执行多次：

```python
for number in range(3):
    print(number)
```

输出：

```text
0
1
2
```

今天学习的两种控制结构分别解决两类问题：

| 结构 | 解决的问题 | 本项目中的用途 |
|---|---|---|
| 分支 | 条件不同，执行不同代码 | 根据分数判断等级 |
| 循环 | 重复执行相似操作 | 连续读取和处理 5 个分数 |

## 6. 布尔值：分支判断的直接依据

### 6.1 `True` 和 `False`

Python 的布尔类型 `bool` 只有两个值：

```python
True
False
```

注意首字母必须大写。下面是错误写法：

```python
true
false
```

比较表达式会产生布尔值：

```python
score = 90

print(score >= 60)  # True
print(score < 60)   # False
print(score == 90)  # True
```

可以检查结果类型：

```python
result = score >= 60
print(result)
print(type(result))
```

输出：

```text
True
<class 'bool'>
```

### 6.2 比较运算符

| 运算符 | 含义 | 示例 | 结果 |
|:---:|---|---|:---:|
| `>` | 大于 | `90 > 60` | `True` |
| `<` | 小于 | `59 < 60` | `True` |
| `>=` | 大于或等于 | `60 >= 60` | `True` |
| `<=` | 小于或等于 | `100 <= 100` | `True` |
| `==` | 等于 | `90 == 90` | `True` |
| `!=` | 不等于 | `90 != 60` | `True` |

最容易混淆的是 `=` 和 `==`：

```python
score = 90       # 把 90 赋给 score
score == 90      # 判断 score 是否等于 90
```

在 `if` 条件中误写单个 `=` 会产生语法错误。

### 6.3 链式比较

Python 可以直接表达一个数位于某个区间：

```python
score = 85
print(80 <= score < 90)
```

这等价于：

```python
print(score >= 80 and score < 90)
```

对于成绩合法范围，可以写：

```python
0 <= score <= 100
```

这种写法比下面的表达式更接近数学习惯：

```python
score >= 0 and score <= 100
```

### 6.4 逻辑运算符

三个常用逻辑运算符：

| 运算符 | 含义 | 例子 |
|---|---|---|
| `and` | 两边都为真才为真 | `score >= 0 and score <= 100` |
| `or` | 至少一边为真就为真 | `score < 0 or score > 100` |
| `not` | 把真假反转 | `not 0 <= score <= 100` |

下面三种写法表达相同的非法分数判断：

```python
score < 0 or score > 100
```

```python
not (score >= 0 and score <= 100)
```

```python
not 0 <= score <= 100
```

本教程的完整程序使用第三种，因为它最短，而且合法范围一眼可见。

### 6.5 不要把字符串和数字直接比较

`input()` 返回字符串：

```python
raw = input("请输入分数：")
```

下面的代码会失败：

```python
if raw >= 60:
    print("及格")
```

因为 `raw` 是 `str`，`60` 是 `int`，Python 不能这样比较。

必须先转换：

```python
score = float(raw)

if score >= 60:
    print("及格")
```

## 7. 单分支：满足条件才执行

最简单的分支结构：

```python
if 条件:
    条件成立时执行的代码
```

示例：

```python
score = 75

if score >= 60:
    print("及格")
```

逐部分理解：

| 部分 | 作用 |
|---|---|
| `if` | 开始一次条件判断 |
| `score >= 60` | 产生 `True` 或 `False` 的条件表达式 |
| `:` | 表示条件头结束，下面开始代码块 |
| 四个空格 | 表示这行属于 `if` 代码块 |

如果条件为 `False`，缩进代码块会被跳过。

### 7.1 缩进决定代码属于哪个分支

```python
score = 50

if score >= 60:
    print("及格")
    print("可以获得学分")

print("程序结束")
```

前两条 `print()` 属于 `if`。最后一条没有缩进，所以无论是否及格都会执行。

错误缩进可能产生两类问题：

- 缩进格式本身不合法，产生 `IndentationError`。
- 代码可以运行，但某一行归属错误，得到错误结果。

第二类更危险，因为程序不会主动告诉你逻辑错了。

### 7.2 代码块不能为空

下面的代码不完整：

```python
if score >= 60:
```

临时还没想好内容时，可以使用 `pass`：

```python
if score >= 60:
    pass
```

`pass` 什么也不做，只用于保持语法完整。正式代码中不需要它时应删除。

## 8. 双分支：二选一

```python
score = 55

if score >= 60:
    print("及格")
else:
    print("不及格")
```

`if` 和 `else` 中只会执行一个代码块：

- 条件为 `True`，执行 `if`。
- 条件为 `False`，执行 `else`。

这叫互斥分支。

不需要给 `else` 再写条件，因为它表示“前面的条件不成立时剩下的所有情况”。

错误写法：

```python
if score >= 60:
    print("及格")
else score < 60:
    print("不及格")
```

正确写法：

```python
if score >= 60:
    print("及格")
else:
    print("不及格")
```

## 9. 多分支：`if / elif / else`

成绩等级有五种结果，需要多分支：

```python
score = 85

if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
elif score >= 60:
    grade = "D"
else:
    grade = "F"

print(grade)
```

输出：

```text
B
```

### 9.1 Python 怎样执行多分支

Python 从上到下检查条件：

1. 检查 `score >= 90`，85 不满足。
2. 检查 `score >= 80`，85 满足。
3. 执行该分支，把 `grade` 设为 `"B"`。
4. 跳过后续所有 `elif` 和 `else`。

关键规则：多分支中只执行第一个成立的分支。

### 9.2 为什么从高分向低分判断

对于 95 分：

- 它大于等于 90。
- 也大于等于 80、70、60。

如果从高到低判断，第一个成立的条件是 A，结果正确。

如果错误地从低到高判断：

```python
if score >= 60:
    grade = "D"
elif score >= 70:
    grade = "C"
elif score >= 80:
    grade = "B"
elif score >= 90:
    grade = "A"
else:
    grade = "F"
```

95 在第一个条件 `score >= 60` 就会被判为 D，后面的 A 永远没有机会执行。

处理递增门槛时，通常从最高门槛向最低门槛判断。

### 9.3 为什么不必重复写上界

判断 B 时只写：

```python
elif score >= 80:
```

不必写：

```python
elif 80 <= score < 90:
```

原因是能够到达第二个分支，已经说明第一个 `score >= 90` 不成立，也就是 `score < 90`。上界已经由前面的失败条件隐含保证。

把多分支理解为逐步缩小剩余范围：

| 到达位置 | 已经知道的事实 | 当前条件成立后的范围 |
|---|---|---|
| `if score >= 90` | 尚无限制 | 90～100 |
| `elif score >= 80` | 已知 `< 90` | 80～不足 90 |
| `elif score >= 70` | 已知 `< 80` | 70～不足 80 |
| `elif score >= 60` | 已知 `< 70` | 60～不足 70 |
| `else` | 已知 `< 60` | 0～不足 60 |

## 10. 边界值：规则最容易出错的位置

边界值是分类规则发生变化的位置。成绩等级的边界包括：

```text
60、70、80、90
```

测试一个边界时，通常至少检查三个点：

```text
边界前一个值、边界本身、边界后一个值
```

例如测试 60：

| 输入 | 预期等级 | 验证目标 |
|---:|:---:|---|
| 59 | F | 60 以下仍是 F |
| 60 | D | 下界包含 60 |
| 61 | D | 进入 D 后仍稳定 |

原始课程要求至少测试：

| 输入 | 预期 |
|---:|:---:|
| 59 | F |
| 60 | D |
| 69 | D |
| 70 | C |
| 89 | B |
| 90 | A |

还建议补充：0、79、80、99、100。

### 10.1 常见的边界错误

错误一：把 `>=` 写成 `>`。

```python
if score > 90:
    grade = "A"
```

这样 90 不属于 A，会错误落入 B。

错误二：人为写出重叠范围。

```python
if 90 <= score <= 100:
    grade = "A"
elif 80 <= score <= 90:
    grade = "B"
```

90 同时满足 A 和 B。由于 `elif` 只取第一个，当前顺序可能暂时得到 A，但规则本身含糊，顺序变化就可能出错。

错误三：人为写出空隙。

```python
if 90 < score <= 100:
    grade = "A"
elif 80 <= score < 90:
    grade = "B"
```

90 既不属于 A，也不属于 B。

从高到低只写下界，可以明显减少重叠和空隙。

## 11. 把等级规则封装成函数

```python
def grade_for(score: float) -> str:
    if score >= 90:
        return "A"
    if score >= 80:
        return "B"
    if score >= 70:
        return "C"
    if score >= 60:
        return "D"
    return "F"
```

这里使用连续的 `if`，而不是 `elif`，仍然是正确的。原因是每个成立的分支都会立即 `return`，函数在此结束，后续条件不会继续执行。

也可以写成更直观的多分支形式：

```python
def grade_for(score: float) -> str:
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 70:
        return "C"
    elif score >= 60:
        return "D"
    else:
        return "F"
```

初学阶段推荐第二种，它更清楚地表达“五选一”的关系。完整项目将使用第二种。

### 11.1 `return` 为什么适合这里

`grade_for()` 的职责是接收一个分数，交回一个等级：

```text
85.0 → grade_for → "B"
```

它不负责读取键盘，也不负责打印统计报告。因此可以直接测试：

```python
print(grade_for(59))
print(grade_for(60))
print(grade_for(90))
```

预期：

```text
F
D
A
```

### 11.2 函数的输入约定

本教程约定：`grade_for()` 接收的分数已经通过 0～100 合法性检查。

这样职责分工是：

- `read_score()`：负责把用户输入变成 0～100 的合法数字。
- `grade_for()`：负责把合法分数映射成等级。
- `main()`：负责重复 5 次、累计并输出。

一个函数只承担一个主要职责，代码更容易理解和测试。

## 12. `for` 循环：重复固定次数

读取 5 个分数是一个明确的固定次数任务，最适合 `for` 循环。

```python
for index in range(5):
    print(index)
```

输出：

```text
0
1
2
3
4
```

虽然输出从 0 到 4，但总共正好执行 5 次。

### 12.1 `range()` 不包含终点

```python
range(5)
```

可以理解为生成：

```text
0, 1, 2, 3, 4
```

不包含 5。

常见形式：

| 写法 | 产生的整数 |
|---|---|
| `range(5)` | 0、1、2、3、4 |
| `range(1, 6)` | 1、2、3、4、5 |
| `range(2, 10, 2)` | 2、4、6、8 |

为了让提示直接显示“第 1 个”到“第 5 个”，本项目使用：

```python
for index in range(1, 6):
    print(f"请输入第 {index} 个分数")
```

### 12.2 循环体由缩进决定

```python
for index in range(1, 6):
    print(f"开始处理第 {index} 个分数")
    print("这行每轮都执行")

print("这行只在循环全部结束后执行一次")
```

循环体中的每一行都要保持一致缩进。

### 12.3 不复制五段代码

不推荐：

```python
score1 = float(input("分数 1："))
score2 = float(input("分数 2："))
score3 = float(input("分数 3："))
score4 = float(input("分数 4："))
score5 = float(input("分数 5："))
```

推荐：

```python
for index in range(1, 6):
    score = float(input(f"请输入第 {index} 个分数："))
```

循环的优势不仅是少写几行。更重要的是：

- 输入次数变化时只需改一个数字。
- 输入校验只需写一份。
- 统计规则只需写一份。
- 修复错误时不会漏改其中某一份。

## 13. 累计变量：在循环中保存进度

循环每轮结束后，局部计算结果如果不保存，就无法得到最终统计。

### 13.1 累计总分

```python
total = 0.0

for index in range(1, 6):
    score = float(input(f"请输入第 {index} 个分数："))
    total = total + score

print(total)
```

可以简写为：

```python
total += score
```

如果输入 80、90、70、60、100，`total` 的变化是：

| 轮次 | 当前分数 | 更新前 `total` | 更新后 `total` |
|---:|---:|---:|---:|
| 1 | 80 | 0 | 80 |
| 2 | 90 | 80 | 170 |
| 3 | 70 | 170 | 240 |
| 4 | 60 | 240 | 300 |
| 5 | 100 | 300 | 400 |

最终平均分：

```python
average = total / 5
```

### 13.2 初始化必须在循环外

错误写法：

```python
for index in range(1, 6):
    total = 0.0
    score = float(input(f"请输入第 {index} 个分数："))
    total += score
```

每一轮都会把 `total` 清零，最后只留下第 5 个分数。

正确写法：

```python
total = 0.0

for index in range(1, 6):
    score = float(input(f"请输入第 {index} 个分数："))
    total += score
```

### 13.3 更新最高分

由于合法分数范围是 0～100，可以把最高分初始化为 0：

```python
highest = 0.0

for index in range(1, 6):
    score = float(input(f"请输入第 {index} 个分数："))

    if score > highest:
        highest = score
```

每一轮都在问：当前分数是否比已知最高分更高？

如果输入 70、85、82、96、90：

| 当前分数 | 更新前最高分 | 是否更新 | 更新后最高分 |
|---:|---:|:---:|---:|
| 70 | 0 | 是 | 70 |
| 85 | 70 | 是 | 85 |
| 82 | 85 | 否 | 85 |
| 96 | 85 | 是 | 96 |
| 90 | 96 | 否 | 96 |

为什么这里能从 0 开始？因为输入校验保证所有合法分数都不小于 0。

如果处理的数据允许负数，把最高值初始化为 0 可能错误。更通用的做法是使用第一个真实数据作为初值，但今天先利用成绩的明确范围降低复杂度。

## 14. 字典累计：按等级保存人数

原始任务明确要求使用字典累计等级分布。

先创建五个计数器：

```python
grade_counts = {
    "A": 0,
    "B": 0,
    "C": 0,
    "D": 0,
    "F": 0,
}
```

这里：

- `"A"`、`"B"` 等是键，也就是类别名称。
- `0` 是对应的值，也就是当前人数。
- 每个“键: 值”组合叫一个键值对。

读取某个等级的人数：

```python
print(grade_counts["A"])
```

把 A 的人数增加 1：

```python
grade_counts["A"] += 1
```

如果等级保存在变量中：

```python
grade = "B"
grade_counts[grade] += 1
```

这行会更新 `grade_counts["B"]`。

### 14.1 为什么字典比五个独立变量更适合

可以写五个变量：

```python
a_count = 0
b_count = 0
c_count = 0
d_count = 0
f_count = 0
```

但更新时又需要一整套分支：

```python
if grade == "A":
    a_count += 1
elif grade == "B":
    b_count += 1
# 后面还要继续写
```

字典把“类别名称”和“计数值”关联起来，只需一行统一更新：

```python
grade_counts[grade] += 1
```

这是今天最重要的抽象之一：变化的是键，不变的是“对应计数加 1”这个操作。

### 14.2 输出字典中的全部等级

为了固定输出顺序，可以写：

```python
for grade in ("A", "B", "C", "D", "F"):
    print(f"{grade}: {grade_counts[grade]} 人")
```

这里的圆括号表示一个固定顺序的数据集合。元组会在第三天系统学习；今天只需知道循环会依次取得 A、B、C、D、F。

## 15. `while` 循环：直到输入合格为止

`for` 适合已知次数，`while` 适合“只要条件成立就继续”。

基本形式：

```python
while 条件:
    重复执行的代码
```

示例：

```python
count = 1

while count <= 3:
    print(count)
    count += 1
```

输出：

```text
1
2
3
```

执行过程：

1. 检查 `count <= 3`。
2. 条件成立，执行循环体。
3. `count += 1` 改变循环条件涉及的变量。
4. 回到循环顶部重新检查。
5. `count` 变成 4 后条件不成立，退出循环。

### 15.1 无限循环

如果忘记改变条件：

```python
count = 1

while count <= 3:
    print(count)
```

`count` 永远是 1，循环永远不会自然结束。

如果终端中出现意外无限循环，可以按 `Ctrl+C` 中断。

### 15.2 `while True` 与主动返回

读取用户输入时，不知道用户会错几次，因此可以写：

```python
def read_score(index: int) -> float:
    while True:
        raw = input(f"请输入第 {index} 个分数：")

        try:
            score = float(raw)
        except ValueError:
            print("输入无效，请输入数字。")
            continue

        if not 0 <= score <= 100:
            print("分数必须在 0 到 100 之间。")
            continue

        return score
```

`while True` 本身没有自然结束条件，但合法输入会执行 `return score`，直接结束函数，因此不会继续循环。

这个函数的行为是：

```text
输入无法转成数字 → 提示 → 回到循环顶部
输入是数字但超出范围 → 提示 → 回到循环顶部
输入是 0～100 → 返回分数 → 函数结束
```

## 16. `continue`、`break` 和 `return` 的区别

### 16.1 `continue`

`continue` 跳过当前轮剩余代码，直接进入下一轮条件检查。

```python
for number in range(1, 6):
    if number == 3:
        continue
    print(number)
```

输出：

```text
1
2
4
5
```

3 这一轮遇到 `continue`，所以没有执行 `print(number)`。

### 16.2 `break`

`break` 立即结束当前循环：

```python
for number in range(1, 6):
    if number == 3:
        break
    print(number)
```

输出：

```text
1
2
```

### 16.3 `return`

`return` 结束的是整个函数，不只是循环：

```python
def find_first_large_number() -> int:
    for number in range(1, 10):
        if number >= 5:
            return number
    return -1
```

### 16.4 本项目怎样选择

| 需求 | 使用 |
|---|---|
| 当前输入无效，重新询问同一个分数 | `continue` |
| 合法分数已经得到，结束读取函数 | `return` |
| 用户输入特定退出命令，提前终止循环 | `break`，但本项目暂不需要 |

## 19. 完整参考实现

把以下内容保存到：

```text
D:\Agent\ai-agent-road\exercises\week01\day02\day02.py
```

```python
SCORE_COUNT = 5


def grade_for(score: float) -> str:
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 70:
        return "C"
    elif score >= 60:
        return "D"
    else:
        return "F"


def read_score(index: int) -> float:
    while True:
        raw = input(f"请输入第 {index} 个分数：")

        try:
            score = float(raw)
        except ValueError:
            print("输入无效，请输入数字。")
            continue

        if not 0 <= score <= 100:
            print("分数必须在 0 到 100 之间。")
            continue

        return score


def main() -> None:
    total = 0.0
    highest = 0.0
    grade_counts = {
        "A": 0,
        "B": 0,
        "C": 0,
        "D": 0,
        "F": 0,
    }

    for index in range(1, SCORE_COUNT + 1):
        score = read_score(index)
        total += score
        highest = max(highest, score)

        grade = grade_for(score)
        grade_counts[grade] += 1

    average = total / SCORE_COUNT

    print("\n统计结果")
    print(f"平均分：{average:.2f}")
    print(f"最高分：{highest:.2f}")
    print("等级分布：")

    for grade in ("A", "B", "C", "D", "F"):
        print(f"  {grade}: {grade_counts[grade]} 人")


if __name__ == "__main__":
    main()
```

### 19.1 一组完整运行示例

输入：

```text
95
82
70
60
59
```

预期统计：

```text
统计结果
平均分：73.20
最高分：95.00
等级分布：
  A: 1 人
  B: 1 人
  C: 1 人
  D: 1 人
  F: 1 人
```

### 19.2 为什么这份实现没有保存全部分数

当前任务只需要总分、最高分和等级人数。每个分数处理完成后，程序只需保留汇总状态：

```text
total + highest + grade_counts
```

因此不必保存一个完整分数列表。这叫流式累计：每条数据只处理一次，立即更新统计状态。

如果后续需要中位数、排序结果或再次逐项查看，就需要保存全部分数。列表会在第三天系统学习。

### 19.3 为什么完整版本使用 `max()` 更新最高分

分步学习时使用的是：

```python
if score > highest:
    highest = score
```

完整版本将它写成：

```python
highest = max(highest, score)
```

`max()` 会返回两个值中更大的一个，因此两种写法结果相同。前一种更适合观察“满足条件才更新”的过程；后一种更简洁，并符合当前项目的 Ruff 风格规则。

### 19.4 为什么 `SCORE_COUNT` 使用大写

```python
SCORE_COUNT = 5
```

全大写名称表示它被当作常量使用。Python 不会禁止重新赋值，但大写命名提醒读者：这个值是程序配置，不应在运行过程中随意改变。

这样循环次数和平均分除数共享同一个值：

```python
range(1, SCORE_COUNT + 1)
total / SCORE_COUNT
```

如果将来把人数改成 10，只改一处即可，避免循环 10 次却仍除以 5。

## 22. 常见错误与排查方法

### 22.1 所有分数都被判成 D

可能原因：从低门槛向高门槛判断。

错误：

```python
if score >= 60:
    grade = "D"
elif score >= 70:
    grade = "C"
```

修复：从 90、80、70、60 依次判断。

### 22.2 90 被判成 B

可能原因：A 的条件写成了 `score > 90`。

修复：

```python
if score >= 90:
```

边界本身是否包含在范围里，由 `>` 和 `>=` 的差异决定。

### 22.3 等级人数总和大于 5

可能原因：使用了五个彼此独立的 `if`，并在多个条件中累计。

错误示例：

```python
if score >= 90:
    grade_counts["A"] += 1
if score >= 80:
    grade_counts["B"] += 1
if score >= 70:
    grade_counts["C"] += 1
```

95 会同时计入 A、B、C 等多个等级。

修复：先用互斥分支得到唯一 `grade`，再统一累计一次：

```python
grade = grade_for(score)
grade_counts[grade] += 1
```

### 22.4 平均分只和最后一个输入有关

可能原因：`total = 0.0` 写在循环内部，每轮都清零。

修复：把累计变量初始化移到循环前。

### 22.5 平均分除数写错

可能原因：循环次数和除数分别写成两个数字，修改时只改了一处。

修复：统一使用 `SCORE_COUNT`。

### 22.6 循环执行 4 次或 6 次

检查 `range()` 的终点不包含规则。

需要 1～5：

```python
range(1, 6)
```

或：

```python
range(1, SCORE_COUNT + 1)
```

### 22.7 输入错误后跳到了下一个学生

可能原因：输入校验放在外层 `for` 中，错误后直接进入下一轮。

修复：让 `read_score()` 内部用 `while True` 反复询问，只有合法后才 `return`。

### 22.8 程序一直询问同一个分数

如果输入始终非法，这是预期行为。

如果输入合法仍不退出，检查：

- `return score` 是否缩进在 `while` 内。
- 合法分数是否误写了 `continue`。
- 范围条件是否写反。

### 22.9 `KeyError`

例如：

```text
KeyError: 'E'
```

说明程序尝试访问字典中不存在的键。检查 `grade_for()` 是否只返回 A、B、C、D、F，以及字典是否包含完全相同的五个键。

字符串区分大小写，`"a"` 和 `"A"` 是不同键。

### 22.10 `IndentationError`

Python 用缩进表示代码块。统一使用四个空格，不要混用 Tab 和空格。

重点检查：

- `if`、`elif`、`else` 是否对齐。
- `for` 和 `while` 的循环体是否缩进。
- `try` 和 `except` 是否对齐。
- 函数体是否统一缩进一级。

### 22.11 `SyntaxError` 指向冒号附近

检查 `if`、`elif`、`else`、`for`、`while`、`def` 行末是否有英文冒号 `:`。

也要检查是否误用了中文括号、中文引号或中文冒号。

### 22.12 `ValueError` 仍然显示 traceback

检查 `float(raw)` 是否确实位于 `try` 代码块中：

```python
try:
    score = float(raw)
except ValueError:
    ...
```

不要把转换放在 `try` 前面。

### 22.13 最高分总是 0

检查更新条件是否写反。

正确：

```python
if score > highest:
    highest = score
```

不是：

```python
if score < highest:
    highest = score
```

后者实际在尝试寻找更低的值。

## 23. 如何系统定位逻辑错误

逻辑错误通常不会产生 traceback，只会给出错误答案。可以使用“打印中间状态”的方法。

在循环末尾临时加入：

```python
print(
    f"调试：index={index}, score={score}, grade={grade}, "
    f"total={total}, highest={highest}, counts={grade_counts}"
)
```

输入 95、82、70、60、59，逐轮对照第 20 节的状态表。

定位完成后删除调试输出，保留正式结果。

推荐排查顺序：

1. 确认当前 `score` 是预期数字。
2. 确认 `grade` 是唯一正确等级。
3. 确认 `total` 只增加一次。
4. 确认 `highest` 只在更高时更新。
5. 确认字典只有当前等级增加 1。
6. 确认五轮后等级总人数等于 5。

一次只检查一个状态，比同时盯着全部代码更有效。

## 24. 必须能口头解释的知识点

### 24.1 `if / elif / else` 怎样工作

合格解释应包含：

- 条件表达式产生 `True` 或 `False`。
- Python 从上到下检查。
- 执行第一个成立的分支后，跳过同组后续分支。
- 如果都不成立，就执行 `else`。

### 24.2 为什么等级要从高到低判断

高分会同时满足多个“至少多少分”的条件。从最高门槛开始，第一次命中就是最准确的等级；如果从 60 开始，95 会过早命中 D。

### 24.3 为什么 59/60、69/70、89/90 必须测试

这些值位于规则切换处，能直接暴露 `>` 与 `>=` 写错、上下界重叠、上下界留空等问题。只测试 75、85 之类的区间中间值，无法证明边界正确。

### 24.4 `for` 和 `while` 有什么区别

- 已知重复 5 次，用 `for`。
- 不知道用户几次才能输入正确，用 `while`。
- 两者都可能用在同一项目中，解决不同层级的重复问题。

### 24.5 `continue` 做什么

它停止当前这一轮剩余代码，回到循环开头进入下一轮检查。本项目用它在输入非法时重新询问。

### 24.6 为什么使用字典累计

等级名称是键，人数是值。当前等级保存在变量 `grade` 中，因此一条 `grade_counts[grade] += 1` 就能更新任意等级，避免为 A～F 分别复制更新代码。

### 24.7 为什么累计变量放在循环外

它们必须在多轮之间保留状态。放进循环会每轮重新初始化，失去之前的统计结果。

### 24.8 为什么要拆分函数

- 等级规则可以脱离键盘输入单独测试。
- 输入错误处理只写一次。
- 主流程更接近业务步骤，阅读更容易。
- 后续改成 API 或读取文件时，等级规则仍可复用。

### 32.7 挑战练习：人数由用户决定

```python
def read_positive_count() -> int:
    while True:
        raw = input("请输入分数个数：")

        try:
            count = int(raw)
        except ValueError:
            print("人数必须是整数。")
            continue

        if count <= 0:
            print("人数必须大于 0。")
            continue

        return count


def main() -> None:
    score_count = read_positive_count()
    total = 0.0
    highest = 0.0
    grade_counts = {"A": 0, "B": 0, "C": 0, "D": 0, "F": 0}

    for index in range(1, score_count + 1):
        score = read_score(index)
        total += score

        if score > highest:
            highest = score

        grade = grade_for(score)
        grade_counts[grade] += 1

    average = total / score_count

    print(f"平均分：{average:.2f}")
    print(f"最高分：{highest:.2f}")

    for grade in ("A", "B", "C", "D", "F"):
        print(f"{grade}: {grade_counts[grade]} 人")
```

`int("2.5")` 会产生 `ValueError`，因此会进入错误提示并重新询问；`int("2")` 才能成功得到整数 2。

assert grade_for(69) == "D"

assert grade_for(79) == "C"
